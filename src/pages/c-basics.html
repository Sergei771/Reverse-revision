Langage C pour le Reverse Engineering

Pourquoi le C est important en Reverse

Le langage C est fondamental en reverse engineering car de nombreux systèmes d'exploitation, applications et logiciels malveillants sont écrits en C. Sa proximité avec le matériel et sa gestion explicite de la mémoire en font un langage dont la compréhension est essentielle pour analyser les binaires.

Pointeurs et Gestion de Mémoire

Les pointeurs sont des variables qui stockent des adresses mémoire et sont cruciaux pour comprendre la mémoire d'un programme.

Déclaration et initialisation

int *ptr;         // Déclare un pointeur vers un int
int value = 42;
ptr = &value;     // ptr contient l'adresse de value
int dereference = *ptr;  // dereference contient 42

Représentation mémoire

Variable Adresse Contenu
value 0x1000 42
ptr 0x2000 0x1000
dereference 0x3000 42

Arithmétique des pointeurs

int array[5] = {10, 20, 30, 40, 50};
int *p = array;  // p pointe vers le premier élément

// Accès aux éléments du tableau via pointeur
printf("%d\n", *p);        // Affiche 10
printf("%d\n", *(p + 2));  // Affiche 30 (p + 2 * sizeof(int))
printf("%d\n", p[3]);      // Affiche 40 (syntaxe alternative)

Comprendre les Opérations sur les Pointeurs

Les pointeurs sont puissants mais nécessitent une compréhension claire de leur interaction avec la mémoire. Reprenons les opérations clés :

int main() {
    int value = 42;
    int anotherValue = 100;
    int *ptr = NULL; // Bonne pratique: initialiser les pointeurs à NULL

    // 1. Opérateur 'Adresse de' (&)
    ptr = &value; 
    // Maintenant, 'ptr' contient l'ADRESSE où 'value' (42) est stockée.
    // Supposons que 'value' est à l'adresse 0x7ffc12345678.
    // Alors, ptr vaut 0x7ffc12345678.

    // 2. Opérateur de Déréférencement (*)
    int retrievedValue = *ptr;
    // '*' lit la VALEUR à l'adresse contenue dans 'ptr'.
    // Donc, retrievedValue vaut 42.
    // *ptr peut aussi être utilisé pour MODIFIER la valeur pointée:
    *ptr = 50; // La variable 'value' vaut maintenant 50!

    // 3. Arithmétique des pointeurs (basée sur le type pointé!)
    ptr = &value; // ptr pointe sur 'value'
    // Supposons sizeof(int) == 4 octets.
    // ptr + 1 ne signifie PAS ajouter 1 à l'adresse !
    // Cela signifie: avancer de sizeof(type_pointé) octets.
    int *nextAddress = ptr + 1; 
    // Si ptr = 0x7ffc12345678, alors nextAddress = 0x7ffc1234567C (adresse + 4 octets).
    // ATTENTION: 'nextAddress' pointe maintenant vers une zone mémoire APRES 'value'.
    //           Ce qu'elle contient est indéfini ici.
    //           L'arithmétique est surtout utile avec les tableaux.

    // Exemple avec tableau:
    int numbers[3] = {10, 20, 30};
    int *pNumbers = numbers; // ou &numbers[0]
    // pNumbers pointe sur 10

    printf("Valeur: %d\n", *pNumbers); // Affiche 10
    
    pNumbers++; // Avance le pointeur à l'élément suivant (adresse + sizeof(int))
    printf("Valeur: %d\n", *pNumbers); // Affiche 20

    // 4. Relation Tableau/Pointeur
    // array[i] est équivalent à *(array + i)
    printf("Troisième élément: %d\n", numbers[2]);     // Affiche 30
    printf("Troisième élément: %d\n", *(numbers + 2)); // Affiche 30

    return 0;
}

Les structures allouent de l'espace mémoire pour chaque membre séquentiellement (avec potentiellement du padding).

Unions

union Data {
    int i;
    float f;
    char str[20];
};

union Data data;
data.i = 10;    // Utilise le membre i
data.f = 3.14;  // Écrase le membre i

Les unions partagent le même espace mémoire pour tous leurs membres, seul un membre peut être utilisé à la fois.

Exemples : Structures de Données Complexes en C

En reverse engineering, vous rencontrerez souvent des structures de données plus élaborées. Comprendre leur agencement en mémoire est clé.

Liste Chaînée Simple :
#include <stdlib.h> // Pour malloc

struct Node {
    int data;           // Donnée (ex: 4 bytes)
    struct Node *next;  // Pointeur vers le prochain nœud (ex: 4 ou 8 bytes selon l'archi)
};

int main() {
    struct Node *head = NULL;
    struct Node *second = NULL;
    struct Node *third = NULL;

    head = (struct Node*)malloc(sizeof(struct Node));
    second = (struct Node*)malloc(sizeof(struct Node));
    third = (struct Node*)malloc(sizeof(struct Node));

    head->data = 1;      // Assigne 1 à la donnée du premier nœud
    head->next = second; // Fait pointer le premier vers le second

    second->data = 2;
    second->next = third;

    third->data = 3;
    third->next = NULL;  // Fin de la liste

    // ... utiliser la liste ...

    free(third); free(second); free(head); // Ne pas oublier de libérer la mémoire !
    return 0;
}

Représentation Mémoire (Simplifiée) : Chaque nœud est un bloc mémoire alloué (souvent sur le tas via `malloc`). Ce bloc contient la `data` suivie du pointeur `next`. Le pointeur `next` contient l'adresse mémoire du bloc du nœud suivant, formant ainsi une chaîne. L'ordre en mémoire physique n'est pas garanti (les blocs peuvent être dispersés).

Structure Imbriquée et Padding :
struct Point {
    char label; // 1 byte
    // Potentiellement 3 bytes de padding ici sur archi 32/64 bits
    int x;      // 4 bytes
    int y;      // 4 bytes
}; // Taille totale probable: 1 + 3 + 4 + 4 = 12 bytes

struct Rectangle {
    struct Point topLeft;     // 12 bytes (taille de Point)
    struct Point bottomRight; // 12 bytes
    int color;                // 4 bytes
    // Potentiellement du padding à la fin si nécessaire pour aligner un tableau de Rectangles
}; // Taille totale probable: 12 + 12 + 4 = 28 bytes (pourrait être 32 avec padding final)

Points Clés :

  • Alignement : Le compilateur ajoute souvent du "padding" (octets vides) pour que les membres de la structure commencent à des adresses mémoire alignées (multiples de 4 ou 8 par exemple), ce qui optimise l'accès CPU. Le `char label` est suivi de 3 octets de padding pour que `int x` commence à une adresse multiple de 4.
  • Taille : La taille totale d'une structure (`sizeof`) inclut le padding éventuel.
  • Imbrication : Les structures imbriquées sont simplement incluses séquentiellement en mémoire.

En reverse, identifier ces patterns d'accès mémoire (offsets fixes pour les membres, calculs d'adresse pour les pointeurs `next`) aide à reconstruire les structures de données utilisées.

Fonctions et Pile d'Appels

Mécanisme d'appel de fonction

  1. Empiler les arguments (de droite à gauche en x86)
  2. Sauvegarder l'adresse de retour (push EIP/RIP)
  3. Sauter à l'adresse de la fonction
  4. La fonction configure son "frame" (EBP/RBP)
  5. Exécution du corps de la fonction
  6. Nettoyage et restauration du contexte
  7. Retour à l'adresse sauvegardée

Compilation avec GCC/Clang

Comprendre comment le code C est transformé en exécutable est utile. Le processus typique (simplifié) avec GCC ou Clang est :

  1. Préprocesseur : Traite les directives commençant par `#` (`#include`, `#define`). Inclut les fichiers header, remplace les macros. Output : Code C "pur". (`gcc -E code.c`)
  2. Compilateur : Traduit le code C en code assembleur spécifique à l'architecture cible. C'est ici que les optimisations ont lieu. Output : Fichier `.s`. (`gcc -S code.c`)
  3. Assembleur : Convertit le code assembleur en code machine (instructions binaires) et crée un fichier objet (`.o`) contenant ce code, les données, et des informations pour l'édition de liens (table des symboles, informations de relocalisation). (`gcc -c code.s`)
  4. Éditeur de Liens (Linker) : Combine un ou plusieurs fichiers objets avec les bibliothèques nécessaires (statiques ou dynamiques) pour résoudre les références entre fichiers (appels de fonctions, variables globales) et créer l'exécutable final. Output : Exécutable (ex: `a.out`). (`gcc code.o -o executable`)
Options Utiles pour le Debug et le Reverse :

Lors de la compilation de code pour l'analyser (ou lors de la création de cibles pour CTF), certaines options sont très utiles :

OptionDescriptionUsage
`-g`Inclut les informations de débogage (noms de fonctions/variables, numéros de lignes).Essentiel pour GDB. Facilite grandement l'analyse initiale dans Ghidra/IDA.
`-O0`Désactive les optimisations.Le code assembleur généré est plus proche et plus fidèle au code C original, rendant l'analyse plus facile.
`-m32`Compile en mode 32 bits (sur un système 64 bits).Utile pour pratiquer sur des binaires 32 bits ou étudier des exploits spécifiques.
`-fno-stack-protector`Désactive la protection contre les débordements de pile (stack canaries).Simplifie l'étude et l'exploitation des buffer overflows sur la pile. Ne pas utiliser en production !
`-z execstack`Rend la pile exécutable.Permet l'exécution de shellcode injecté sur la pile. Ne pas utiliser en production !
`-no-pie` (GCC) / `-fno-pie` (Clang)Désactive le code indépendant de la position (Position Independent Executable).L'adresse de base du programme est fixe, simplifiant le débogage et l'analyse d'adresses.
 
# Exemple de compilation pour analyse/debug facile (Linux 32-bit)
gcc -m32 -g -O0 -fno-stack-protector -z execstack -no-pie programme.c -o programme_debug
