Bases de l'Assembleur (x86/x64)

Pourquoi l'Assembleur en Reverse Engineering ?

L'assembleur est le langage le plus proche du code machine exécuté par le processeur. Comprendre l'assembleur est essentiel pour analyser ce que fait réellement un programme compilé, identifier les vulnérabilités et comprendre le comportement des malwares, car c'est le langage que les outils comme Ghidra ou IDA affichent lors du désassemblage.

Registres Principaux (x86/x64)

Registres Généraux (General-Purpose Registers - GPRs)

Ces registres sont utilisés pour les opérations arithmétiques, logiques, le stockage temporaire de données, et parfois comme pointeurs. La nomenclature change entre 16, 32 et 64 bits, où les versions plus larges étendent les plus petites (par exemple, modifier EAX affecte AX, AH, AL; modifier RAX affecte EAX, AX, etc.).

Registres de Pointeur et d'Instruction

Ces registres ont des rôles spécifiques liés à la gestion de la pile et au flux d'exécution du programme.

Registre (64/32/16)NomDescription
RSP / ESP / SPStack PointerPointe vers le sommet actuel de la pile. Modifié par `PUSH`, `POP`, `CALL`, `RET` et les allocations/désallocations manuelles.
RBP / EBP / BPBase PointerPointe vers la base du "stack frame" (cadre de pile) de la fonction courante. Utilisé pour accéder aux arguments de fonction et aux variables locales (surtout en 32 bits ou sans optimisations).
RIP / EIP / IPInstruction PointerContient l'adresse de la prochaine instruction à exécuter par le processeur. Modifié par les sauts (`JMP`, `Jcc`), les appels (`CALL`) et les retours (`RET`). Ne peut pas être modifié directement par la plupart des instructions (sauf sauts/appels).

Registres de Segment et EFLAGS/RFLAGS

Les registres de segment (CS, DS, SS, ES, FS, GS) étaient cruciaux dans les anciens modes d'adressage pour définir des blocs de mémoire. En mode protégé 64 bits moderne (Linux/Windows), ils ont un rôle très limité. CS pointe toujours vers le segment de code, SS vers le segment de pile, DS/ES sont peu utilisés. FS ou GS sont souvent utilisés pour accéder à des structures spécifiques au thread (Thread Local Storage - TLS), comme le Thread Environment Block (TEB) sous Windows.

Le registre EFLAGS (32 bits) / RFLAGS (64 bits) contient des indicateurs (flags) qui reflètent l'état du processeur et le résultat de la dernière opération effectuée. Ils sont fondamentaux pour le contrôle de flux conditionnel.

Instructions Courantes (Syntaxe Intel)

Note: La syntaxe Intel (`instruction destination, source`) est couramment utilisée par les outils Windows et les désassembleurs comme IDA Pro et Ghidra par défaut. La syntaxe AT&T (`instruction %source, %destination`) est souvent vue dans les outils GNU/Linux.

Mouvement de Données

Ces instructions servent à copier des données entre registres, entre registres et mémoire, ou à charger des valeurs immédiates.

  • MOV (Move): Copie la valeur de la `source` vers la `destination`. Ne modifie pas les flags. La taille des opérandes doit correspondre (ex: `mov eax, ebx` mais pas `mov ax, ebx`).
  • LEA (Load Effective Address): Calcule l'adresse de l'opérande `source` (qui doit être une adresse mémoire) et la place dans le registre `destination`. Crucial pour calculer des adresses sans accéder à la mémoire. Ne modifie pas les flags.
section .data
    myVar dd 123      ; Variable 32 bits initialisée à 123
    myArray dw 10, 20, 30 ; Tableau de 3 mots (16 bits)

section .text
    ; Exemple MOV
    mov eax, 10          ; Met la valeur immédiate 10 dans EAX
    mov ebx, eax         ; Copie le contenu de EAX dans EBX
    mov ecx, [myVar]     ; Copie la valeur (123) de l'adresse myVar dans ECX
    mov [myVar], edx     ; Copie le contenu de EDX à l'adresse mémoire de myVar
    mov ax, [myArray+2]  ; Copie le 2ème élément (20) du tableau dans AX (+2 car 16 bits/word)

    ; Exemple LEA
    lea esi, [myArray]   ; Met l'adresse de myArray dans ESI (pointeur)
    lea edi, [ebp-8]     ; Met l'adresse de la variable locale (sur la pile) dans EDI
    lea eax, [ebx+ecx*4+100h] ; Calcule l'adresse complexe et la met dans EAX

Opérations Arithmétiques

Effectuent des calculs mathématiques de base. Affectent les flags (ZF, SF, CF, OF, PF, AF).

  • ADD destination, source: Ajoute `source` à `destination` (`destination = destination + source`).
  • SUB destination, source: Soustrait `source` de `destination` (`destination = destination - source`). Souvent utilisé pour comparer (`CMP` est une soustraction qui ne stocke pas le résultat mais affecte les flags).
  • INC destination: Incrémente `destination` de 1. Plus court et parfois plus rapide que `ADD destination, 1`. N'affecte PAS le Carry Flag (CF).
  • DEC destination: Décrémente `destination` de 1. Plus court et parfois plus rapide que `SUB destination, 1`. N'affecte PAS le Carry Flag (CF).
  • MUL source (non signé) / IMUL source (signé): Multiplie. La destination est implicite (AX, DX:AX, ou EDX:EAX, RDX:RAX selon la taille de `source`). `IMUL` existe aussi en formes 2 et 3 opérandes plus flexibles.
  • DIV source (non signé) / IDIV source (signé): Divise. Le dividende est implicite (AX, DX:AX, EDX:EAX, RDX:RAX). Le quotient est stocké dans AL/AX/EAX/RAX et le reste dans AH/DX/EDX/RDX.
    mov eax, 100
    mov ebx, 50
    add eax, ebx    ; EAX = 150
    sub eax, 20     ; EAX = 130
    inc ebx         ; EBX = 51
    dec eax         ; EAX = 129

    mov ax, 5       ; Pour MUL/DIV 16 bits
    mov bx, 10
    mul bx          ; DX:AX = AX * BX = 5 * 10 = 50

    mov eax, 103    ; Pour IDIV 32 bits
    mov ecx, 10
    cdq             ; Étend EAX en EDX:EAX (sign extension). EDX=0
    idiv ecx        ; EDX:EAX / ECX. EAX = Quotient = 10, EDX = Reste = 3

    imul esi, edi, 5 ; Forme 3 opérandes: ESI = EDI * 5

Opérations Logiques et de Décalage

Effectuent des opérations booléennes bit-à-bit ou des décalages/rotations. Affectent principalement ZF, SF, PF. CF/OF sont affectés différemment selon l'instruction.

  • AND destination, source: ET logique bit-à-bit (`destination = destination & source`). Souvent utilisé pour masquer des bits ou tester si un bit est à 0. Met OF=0, CF=0.
  • OR destination, source: OU logique bit-à-bit (`destination = destination | source`). Souvent utilisé pour mettre des bits à 1. Met OF=0, CF=0.
  • XOR destination, source: OU exclusif bit-à-bit (`destination = destination ^ source`). Utilisé pour inverser des bits ou mettre un registre à zéro (`xor eax, eax`). Met OF=0, CF=0.
  • NOT destination: Inverse tous les bits de `destination` (complément à 1). N'affecte aucun flag.
  • SHL/SAL destination, count: Décalage logique/arithmétique à gauche. Identiques. Décale les bits vers la gauche de `count` positions. Le dernier bit sorti va dans CF. Remplit avec des 0 à droite.
  • SHR destination, count: Décalage logique à droite. Décale les bits vers la droite. Le dernier bit sorti va dans CF. Remplit avec des 0 à gauche (non signé).
  • SAR destination, count: Décalage arithmétique à droite. Décale les bits vers la droite. Le dernier bit sorti va dans CF. Remplit avec le bit de signe à gauche (préserve le signe).
  • ROL/ROR destination, count: Rotation à gauche/droite. Les bits sortis d'un côté rentrent de l'autre. Le dernier bit déplacé va aussi dans CF.
    mov al, 0b11001010
    mov bl, 0b10101100
    and al, bl   ; AL = 0b10001000
    or al, 0b00000011 ; AL = 0b10001011
    xor al, 0b11110000 ; AL = 0b01111011
    not al       ; AL = 0b10000100

    mov cl, 2
    shl al, cl   ; AL = 0b00010000, CF=1 (le dernier 0 sorti)
    sar al, 1    ; AL = 0b00001000, CF=0

    xor ebx, ebx ; Met EBX à 0

Comparaison et Test

Ces instructions sont cruciales pour les branchements conditionnels car elles modifient les flags sans altérer les opérandes.

  • CMP destination, source: Compare `destination` et `source` en effectuant une soustraction (`destination - source`) mais sans stocker le résultat. Affecte les flags (ZF, SF, CF, OF, PF, AF) comme `SUB`. Utilisé pour vérifier l'égalité, la supériorité, l'infériorité, etc.
  • TEST destination, source: Effectue un ET logique bit-à-bit (`destination & source`) sans stocker le résultat. Affecte les flags (ZF, SF, PF) comme `AND` (met CF=0, OF=0). Très utilisé pour vérifier si un ou plusieurs bits spécifiques sont à 1 ou à 0 dans un opérande.
    mov eax, 10
    mov ebx, 5
    cmp eax, ebx ; Compare 10 et 5. Flags: ZF=0, SF=0, CF=0 (10 > 5)
    ; je label_si_egal   ; Ne sautera pas car ZF=0
    ; jg label_si_sup    ; Sautera car SF=OF (implicite) et ZF=0

    cmp eax, 10  ; Compare 10 et 10. Flags: ZF=1, SF=0, CF=0
    ; je label_si_egal   ; Sautera car ZF=1

    mov ecx, 0b1011
    test ecx, 0b0010 ; Teste si le 2ème bit (valeur 2) est à 1.
                     ; Résultat (non stocké) = 0b0010. ZF=0.
    ; jz label_si_bit_zero ; Ne sautera pas

    test ecx, 0b0100 ; Teste si le 3ème bit (valeur 4) est à 1.
                     ; Résultat (non stocké) = 0b0000. ZF=1.
    ; jz label_si_bit_zero ; Sautera car ZF=1

Contrôle de Flux

Ces instructions modifient le registre `RIP`/`EIP` pour changer l'ordre d'exécution des instructions.

  • JMP target: Saut inconditionnel. Transfère l'exécution à l'adresse `target` (une étiquette ou une adresse calculée).
  • Jcc target (Conditional Jumps): Saut conditionnel. Transfère l'exécution à `target` seulement si une condition basée sur les flags est remplie. Il existe de nombreuses conditions :
    • Égalité/Zéro : `JE` (Jump if Equal) / `JZ` (Jump if Zero) -> saute si ZF=1
    • Inégalité/Non Zéro : `JNE` (Jump if Not Equal) / `JNZ` (Jump if Not Zero) -> saute si ZF=0
    • Signé - Supérieur/Inférieur : `JG` (Greater), `JL` (Less), `JGE` (Greater or Equal), `JLE` (Less or Equal) -> basés sur SF, OF, ZF
    • Non signé - Au-dessus/En dessous : `JA` (Above), `JB` (Below), `JAE` (Above or Equal), `JBE` (Below or Equal) -> basés sur CF, ZF
    • Autres : `JS` (Sign), `JNS` (Not Sign), `JC` (Carry), `JNC` (Not Carry), `JO` (Overflow), `JNO` (Not Overflow), `JP` (Parity), `JNP` (Not Parity)
  • CALL target: Appelle une fonction. Empile (`push`) l'adresse de l'instruction suivante (adresse de retour) sur la pile, puis saute (`jmp`) à `target`.
  • RET: Retourne d'une fonction. Dépile (`pop`) l'adresse de retour de la pile et saute (`jmp`) à cette adresse. Peut prendre un opérande optionnel (principalement en `stdcall` 32 bits) pour nettoyer des arguments de la pile.
my_function:
    ; ... corps de fonction ...
    ret

start:
    mov eax, 10
    cmp eax, 20
    jl less_than_20  ; Sautera car 10 < 20 (SF != OF)
    jmp continue_here ; Saut inconditionnel

less_than_20:
    call print_message ; Empile l'adresse de 'continue_here' et saute à print_message
    ; ... (adresse de retour) ...

continue_here:
    ; ... suite du code ...

Manipulation de la Pile (Stack)

La pile est une zone mémoire LIFO (Last-In, First-Out) essentielle pour les appels de fonction, les variables locales et le passage d'arguments. Le registre `RSP`/`ESP` pointe vers le sommet de la pile, qui grandit généralement vers les adresses basses.

  • PUSH source: Décrémente `RSP`/`ESP` de la taille de l'opérande (4 ou 8 octets), puis copie la valeur de `source` à l'adresse pointée par le nouveau `RSP`/`ESP`.
  • POP destination: Copie la valeur depuis l'adresse pointée par `RSP`/`ESP` vers `destination`, puis incrémente `RSP`/`ESP` de la taille de l'opérande.

    mov eax, 111
    mov ebx, 222
    push eax        ; RSP diminue de 4, [RSP] = 111
    push ebx        ; RSP diminue de 4, [RSP] = 222
    ; La pile contient maintenant: 222 (au sommet), 111

    pop ecx         ; ECX = 222, RSP augmente de 4
    pop edx         ; EDX = 111, RSP augmente de 4
    ; ECX=222, EDX=111, RSP revenu à sa valeur initiale

Adressage Mémoire

Modes d'Adressage Mémoire

L'assembleur x86/x64 offre plusieurs façons de spécifier l'emplacement des données (opérandes) pour les instructions, en particulier pour accéder à la mémoire. Comprendre ces modes est crucial pour lire le code désassemblé.

ModeSyntaxe Exemple (Intel)DescriptionUsage typique
Immédiat (Immediate) mov eax, 12345 La donnée est une constante directement incluse dans l'instruction. Initialiser des registres, utiliser des constantes.
Registre (Register) mov eax, ebx La donnée se trouve dans un autre registre. Calculs rapides, manipulation de données temporaires.
Direct Mémoire (Direct) mov eax, [myVariable]
mov eax, [0x401000]		 L'adresse mémoire de la donnée est spécifiée directement comme une constante (souvent une étiquette ou une adresse absolue). Accéder à des variables globales ou statiques à adresse fixe.
Indirect Registre (Register Indirect) mov eax, [ebx] Le registre contient l'adresse mémoire de la donnée. Accéder à des données via un pointeur stocké dans un registre.
Indirect avec Déplacement (Indirect with Displacement) mov eax, [ebx + 8]
mov eax, [ebp - 16]		 L'adresse est calculée en ajoutant un déplacement constant (offset) à la valeur d'un registre. Accéder aux membres d'une structure via un pointeur, accéder aux variables locales/arguments sur la pile via EBP/RBP.
Indexé (Based Indexed) mov eax, [ebx + esi] L'adresse est calculée en ajoutant le contenu de deux registres (un registre de base et un registre d'index). Accéder à des éléments dans des structures de données bidimensionnelles (moins courant que Scaled Indexed).
Indexé avec Déplacement (Based Indexed with Displacement) mov eax, [ebx + esi + 12] L'adresse est la somme d'un registre de base, d'un registre d'index et d'un déplacement constant. Accès complexe à des structures imbriquées ou des tableaux de structures.

Accès aux éléments d'un tableau où l'index est dans `esi` et la taille de l'élément est le facteur d'échelle (ex: 4 pour `int` ou `float`). `ebx` contient l'adresse de base du tableau.
Indexé avec Facteur d'Échelle et Déplacement (Scaled Indexed with Displacement) mov eax, [ebx + esi * 4 + myStruct.arrayOffset]
mov eax, [ebp + esi*8 - 32]		 Forme la plus générale : adresse = base + (index * échelle) + déplacement. Accéder à des éléments d'un tableau à l'intérieur d'une structure, ou d'un tableau de structures sur la pile. 
section .data
    myGlobalVar dd 100
    myArray     dd 10, 20, 30, 40  ; Tableau d'entiers 32 bits (taille 4)

section .bss
    myBuffer resb 256

section .text
    global _start
_start:
    ; Registre
    mov eax, 1          ; Mode Immédiat
    mov ebx, eax        ; Mode Registre

    ; Direct Mémoire
    mov ecx, [myGlobalVar] ; Charge 100 dans ECX

    ; Indirect Registre
    mov esi, myBuffer   ; ESI pointe sur le début de myBuffer
    mov byte [esi], 'A' ; Écrit 'A' au début du buffer

    ; Indirect avec Déplacement
    mov edi, esi        ; EDI pointe aussi sur myBuffer
    mov byte [edi + 1], 'B' ; Écrit 'B' à l'offset 1 du buffer

    ; Indexé avec Facteur d'Échelle (accès à myArray[2])
    mov ebx, myArray    ; EBX = adresse de base de myArray
    mov esi, 2          ; ESI = index
    mov edx, [ebx + esi * 4] ; EDX = myArray[2] (qui est 30)

    ; Indexé avec Facteur d'Échelle et Déplacement
    ; Supposons qu'une structure à [ebp-40] contienne un tableau à l'offset 8
    ; Accès à struct.array[esi] où array est un tableau de mots (taille 2)
    ; mov ax, [ebp + esi * 2 - 32] ; -40 (base struct) + 8 (offset array) = -32

    ; Sortie propre (exemple simple)
    mov eax, 1          ; sys_exit
    xor ebx, ebx        ; code de retour 0
    int 0x80            ; Appel système Linux 32 bits

Conventions d'Appel (Calling Conventions)

Une convention d'appel est un ensemble de règles standardisées qui définissent comment les fonctions sont appelées, comment les arguments sont passés, comment les valeurs sont retournées, et quels registres doivent être préservés. Connaître la convention d'appel est essentiel pour comprendre les interactions entre fonctions.

Conventions 32 bits (x86)

Bien que moins pertinent aujourd'hui, comprendre ces conventions est utile pour analyser d'anciens binaires ou des binaires 32 bits.

Prologue et Épilogue de Fonction

Ce sont des séquences d'instructions standardisées au début et à la fin des fonctions, principalement pour gérer le cadre de pile (`stack frame`). Le cadre de pile est une zone de la pile réservée pour une instance d'appel de fonction, contenant typiquement l'adresse de retour, les arguments (si passés sur la pile), les variables locales et les registres sauvegardés.

Le prologue typique (surtout sans optimisations ou en 32 bits) :

  1. Sauvegarde l'ancien pointeur de base (`push rbp`/`push ebp`).
  2. Établit le nouveau pointeur de base pour le cadre actuel (`mov rbp, rsp` / `mov ebp, esp`).
  3. Alloue de l'espace sur la pile pour les variables locales et les registres temporaires en décrémentant le pointeur de pile (`sub rsp, N` / `sub esp, N`).
  4. (Optionnel) Sauvegarde les registres non-volatils (callee-saved) qui seront utilisés par la fonction.

L'épilogue typique effectue l'inverse pour restaurer l'état avant le retour :

  1. (Optionnel) Restaure les registres non-volatils sauvegardés.
  2. Libère l'espace des variables locales en restaurant l'ancien pointeur de pile (`mov rsp, rbp` / `mov esp, ebp`). L'instruction `leave` combine cette étape et la suivante.
  3. Restaure l'ancien pointeur de base (`pop rbp` / `pop ebp`).
  4. Retourne à l'appelant (`ret`).
; Prologue typique (x64, non optimisé)
push rbp          ; 1. Sauvegarde l'ancien RBP
mov rbp, rsp      ; 2. RBP pointe maintenant vers la base du cadre actuel
sub rsp, 32       ; 3. Alloue 32 octets pour les locales (par exemple)
; push rbx        ; 4. Exemple: sauvegarde du registre non-volatil RBX s'il est utilisé

; ... corps de la fonction ...
; Utilise [rbp - 8], [rbp - 16], etc. pour accéder aux locales

; Épilogue typique (x64, non optimisé)
; pop rbx         ; 1. Restaure RBX
mov rsp, rbp      ; 2. Libère l'espace des locales (alternative: leave)
pop rbp           ; 3. Restaure l'ancien RBP
ret               ; 4. Retourne à l'appelant

; Alternative avec leave (combine mov rsp, rbp et pop rbp)
; ... (corps fonction) ...
; pop rbx
leave
ret

Note: Les compilateurs modernes avec optimisations peuvent omettre le pointeur de base (`RBP`/`EBP`) et accéder aux variables locales directement via des offsets par rapport à `RSP`/`ESP`, rendant le prologue/épilogue plus courts mais l'analyse manuelle parfois plus complexe.
