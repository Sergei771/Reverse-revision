Techniques de Rétro-conception

Approches méthodologiques

La rétro-conception électronique demande une approche structurée pour naviguer dans la complexité des systèmes analysés. Les techniques ci-dessous vous permettront d'aborder efficacement l'analyse d'un binaire.

Analyse Statique

L'analyse statique consiste à examiner le code sans l'exécuter. Elle permet de comprendre la structure et le comportement potentiel du programme.

Techniques d'analyse statique

  1. Identification des chaînes - Localiser les messages, URLs, noms de fichiers
  2. Analyse des imports/exports - Déterminer les bibliothèques et fonctions utilisées
  3. Désassemblage - Convertir le code machine en assembleur
  4. Décompilation - Générer un pseudo-code de haut niveau
  5. Analyse du graphe de flux - Identifier les structures de contrôle
  6. Reconnaissance de patterns - Identifier des algorithmes connus

Outils d'analyse statique

  • strings - Extraire les chaînes de caractères 
    strings -a executable
  • objdump - Désassembler les sections 
    objdump -d executable
  • Ghidra/IDA - Analyse avancée, décompilation

Analyse Dynamique

L'analyse dynamique implique l'exécution du programme pour observer son comportement réel. Elle complète l'analyse statique en révélant des comportements qui pourraient être difficiles à détecter statiquement.

Techniques d'analyse dynamique

  1. Traçage d'exécution - Suivre le flux d'instructions
  2. Breakpoints - Arrêter l'exécution à des points spécifiques
  3. Memory dumps - Examiner la mémoire à des moments clés
  4. API hooking - Intercepter les appels aux fonctions
  5. Tracing réseau - Capturer les communications
  6. Manipulation d'état - Modifier les variables pour tester le comportement

Outils d'analyse dynamique

  • GDB/WinDbg - Débogage et analyse mémoire 
    gdb -q ./executable
(gdb) break main
(gdb) run
(gdb) info registers
  • ltrace/strace - Tracer les appels de bibliothèques/système 
    strace ./executable
  • Wireshark - Capture et analyse du trafic réseau

Reconnaissance des structures en C

Identifier les structures de contrôle et de données est essentiel pour comprendre la logique d'un programme désassemblé.

Structures conditionnelles

if-else en assembleur se traduit par des instructions de comparaison suivies de sauts conditionnels :

Code C
if (a > b) {
    x = 1;
} else {
    x = 2;
}
Désassemblage
  mov eax, [a]
  cmp eax, [b]
  jle else_branch
  mov [x], 1
  jmp end_if
else_branch:
  mov [x], 2
end_if:
Identification Avancée : Conditions

Pour des structures plus complexes :

  • Switch-Case (Jump Table) : Souvent implémenté avec une "jump table". Une valeur initiale est utilisée comme index dans un tableau d'adresses (la table). Le code saute ensuite à l'adresse récupérée. Recherchez des accès mémoire indexés suivis d'un saut indirect (`jmp eax`, `jmp [base + index*size]`). 
    ; Code C: switch(value) { case 0: ...; case 1: ...; }
  mov eax, [value]
  cmp eax, max_case_value ; Vérif boundary
  ja default_case
  jmp [jump_table + eax*4] ; Saut indirect via la table

jump_table:
  dd case_0_addr
  dd case_1_addr
  ...
case_0_addr:
  ; code pour case 0
  jmp end_switch
case_1_addr:
  ; code pour case 1
  jmp end_switch
default_case:
  ; code pour default
end_switch:
  • Conditions Imbriquées (Nested) : Se traduisent par des séquences de `CMP`/`TEST` et `Jcc` imbriquées. Suivez le flux des sauts pour reconstruire la logique. Les niveaux d'indentation dans votre analyse aident à visualiser l'imbrication. 
    ; Code C: if (a > 5) { if (b == 0) { ... } }
  cmp [a], 5
  jle outer_end   ; Condition externe
  cmp [b], 0
  jne inner_end   ; Condition interne
  ; ... code imbriqué ...
inner_end:
outer_end:
  • Utilisation des Flags : Après `CMP a, b`, les flags indiquent la relation :
    • `JE`/`JZ` (Equal/Zero): saute si `a == b` (ZF=1)
    • `JNE`/`JNZ` (Not Equal/Not Zero): saute si `a != b` (ZF=0)
    • `JG`/`JNLE` (Signed Greater): saute si `a > b` (ZF=0 et SF=OF)
    • `JGE`/`JNL` (Signed Greater or Equal): saute si `a >= b` (SF=OF)
    • `JL`/`JNGE` (Signed Less): saute si `a < b` (SF!=OF)
    • `JLE`/`JNG` (Signed Less or Equal): saute si `a <= b` (ZF=1 ou SF!=OF)
    • `JA`/`JNBE` (Unsigned Above): saute si `a > b` (CF=0 et ZF=0)
    • `JAE`/`JNB` (Unsigned Above or Equal): saute si `a >= b` (CF=0)
    • `JB`/`JNAE` (Unsigned Below): saute si `a < b` (CF=1)
    • `JBE`/`JNA` (Unsigned Below or Equal): saute si `a <= b` (CF=1 ou ZF=1)
    Après `TEST reg, mask`, `JZ` saute si tous les bits testés sont 0, `JNZ` saute si au moins un bit testé est 1.

Boucles

while/for en assembleur utilise des comparaisons et des sauts pour créer des boucles :

Code C
for (i = 0; i < 10; i++) {
    sum += i;
}
Désassemblage
  mov [i], 0
loop_start:
  mov eax, [i]
  cmp eax, 10
  jge loop_end
  add [sum], eax
  inc dword [i]
  jmp loop_start
loop_end:
Identification Avancée : Boucles

Différents types de boucles ont des structures typiques :

  • Boucle `while (condition)` : La condition est testée *avant* le corps de la boucle. 
    loop_check:
  ; ... calcule/vérifie la condition ...
  cmp condition_result, 0 ; ou test
  je loop_end             ; Saute si la condition est fausse
  ; ... corps de la boucle ...
  jmp loop_check          ; Retourne vérifier la condition
loop_end:
  • Boucle `do { ... } while (condition)` : Le corps est exécuté au moins une fois, la condition est testée *après*. 
    loop_start:
  ; ... corps de la boucle ...
  ; ... calcule/vérifie la condition ...
  cmp condition_result, 0 ; ou test
  jne loop_start          ; Continue si la condition est vraie
; loop_end: (la sortie se fait par le non-saut)
  • Boucle `for` complexe : Peut inclure plusieurs initialisations, conditions ou incrémentations. Recherchez les blocs d'initialisation avant la boucle, la vérification de condition au début (ou parfois à la fin), et les opérations d'incrémentation/modification à la fin du corps de la boucle avant le saut de retour. 
    ; Code C: for (i=0, j=10; i < j; i++, j--) { ... }
  mov [i], 0
  mov [j], 10
loop_check:
  mov eax, [i]
  cmp eax, [j]
  jge loop_end    ; Condition i < j
  ; ... corps de la boucle ...
  inc dword [i]   ; i++
  dec dword [j]   ; j--
  jmp loop_check
loop_end:

Structures de données

La reconnaissance des structures de données est plus complexe mais peut être facilitée par l'observation des patterns d'accès :

Tableaux

Identifiables par des accès mémoire avec des offsets calculés :

  ; Accès à array[i]
  mov eax, [i]
  mov ebx, 4        ; sizeof(int)
  mul ebx           ; eax = i * 4
  add eax, array    ; eax = &array[i]
  mov edx, [eax]    ; edx = array[i]
Structures

Reconnaissables par des accès à des offsets fixes :

  ; Accès à person.age
  mov eax, [person]
  mov ebx, [eax+8]  ; Offset 8 = age
  
  ; Accès à person.name
  mov eax, [person]
  lea ecx, [eax]    ; Offset 0 = name

Guide Pas à Pas : Rétro-conception d'un Algorithme Simple

Voyons comment appliquer ces techniques pour comprendre une fonction inconnue. Prenons l'exemple d'une fonction C compilée dont nous avons le désassemblage suivant (syntaxe Intel x86 simplifiée) :

// Fonction C originale (inconnue au début)
int simple_hash(char *input) {
    int hash = 0;
    int i = 0;
    while (input[i] != '\0') {
        hash = (hash * 31) + input[i];
        i++;
    }
    return hash;
}
; Désassemblage de la fonction 'simple_hash'
simple_hash:
    push ebp
    mov ebp, esp
    sub esp, 4          ; Alloue espace pour variable locale
    mov dword [ebp-4], 0  ; Initialise la variable locale (hash?) à 0
    
    mov eax, [ebp+8]    ; Récupère l'argument 1 (pointeur 'input'?)
    mov ecx, 0          ; Initialise un compteur (index 'i'?) à 0
    
loop_start:             ; Étiquette de début de boucle
    movzx edx, byte [eax+ecx] ; Lire un caractère depuis input[i]
    test dl, dl         ; Teste si le caractère est null (fin de chaîne?)
    jz loop_end         ; Si null, saute à la fin de la boucle
    
    ; Corps de la boucle
    mov ebx, [ebp-4]    ; Charge la variable locale (hash courant)
    imul ebx, ebx, 31   ; Multiplie par 31
    add ebx, edx        ; Ajoute le caractère lu (ASCII value)
    mov [ebp-4], ebx    ; Met à jour la variable locale (nouveau hash)
    
    inc ecx             ; Incrémente le compteur (i++)
    jmp loop_start      ; Retourne au début de la boucle
    
loop_end:               ; Étiquette de fin de boucle
    mov eax, [ebp-4]    ; Place la variable locale (hash final) dans EAX (valeur de retour)
    leave               ; Restaure EBP et ESP
    ret                 ; Retourne de la fonction

Étapes de l'analyse :

  1. Analyse statique initiale :
    • Nom de la fonction : `simple_hash` (suggère un calcul de hachage).
    • Arguments : Prend un argument passé sur la pile `[ebp+8]`, probablement un pointeur (utilisé comme adresse de base pour lire des octets).
    • Variables locales : Une variable locale `[ebp-4]` (DWORD - 4 octets) est allouée et initialisée à 0.
    • Valeur de retour : La valeur finale de la variable locale est placée dans `EAX` avant `ret`.
  2. Identification de la fonction clé : La fonction entière est notre cible ici. On observe un prologue (`push ebp`, `mov ebp, esp`), une allocation locale (`sub esp, 4`), un épilogue (`leave`, `ret`), et un corps de fonction entre les deux.
  3. Analyse du désassemblage :
    • Initialisation : `[ebp-4]` (hash) mis à 0, `ecx` (index `i`) mis à 0. `eax` contient le pointeur d'entrée.
    • Lecture de caractère : `movzx edx, byte [eax+ecx]` lit un octet (caractère) à l'adresse `input + i`. `movzx` étend à 32 bits avec des zéros.
    • Condition de fin : `test dl, dl` suivi de `jz loop_end` vérifie si le caractère lu est le terminateur null (`\0`).
    • Calcul : `imul ebx, ebx, 31` et `add ebx, edx` effectuent le calcul `hash = hash * 31 + character`.
    • Mise à jour : `mov [ebp-4], ebx` sauvegarde le nouveau hash. `inc ecx` avance l'index.
    • Boucle : `jmp loop_start` continue la boucle.
    • Retour : `mov eax, [ebp-4]` prépare la valeur de retour.
  4. Identification des boucles et conditions :
    • Une boucle `while`-like est clairement visible avec `loop_start`, `loop_end`, la condition `test dl, dl / jz loop_end` (vérifiée avant le corps principal pour chaque itération sauf potentiellement la première dans certaines optimisations), et le `jmp loop_start` à la fin.
    • La condition est `input[i] != '\0'`.
  5. Reconnaissance des opérations clés :
    • Lecture séquentielle d'octets depuis une adresse mémoire (`[eax+ecx]`).
    • Condition d'arrêt sur un octet null.
    • Calcul répétitif impliquant une multiplication (par 31, une constante souvent utilisée dans les hash) et une addition avec la valeur de l'octet lu.
  6. Reconstruction de la logique en pseudo-code : 
    fonction simple_hash(pointeur input):
  variable locale hash = 0
  variable locale index = 0
  
  boucle:
    caractere = lire_octet(input + index)
    si caractere == 0:
      aller à fin_boucle
      
    hash = (hash * 31) + caractere
    index = index + 1
    aller à boucle
    
  fin_boucle:
  retourner hash

    Ce pseudo-code correspond directement à la fonction C `simple_hash` donnée au début.

Cette analyse, même sur un exemple simple, montre comment combiner l'observation des instructions, l'identification des structures de contrôle, et la compréhension des conventions d'appel pour reconstruire la logique d'une fonction à partir de son désassemblage.
